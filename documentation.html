Documentación del repositorio

Este proyecto es una aplicación Next.js tipo dashboard para VAX Solutions. Incluye un panel de métricas y una sección de gestión de envíos, clientes y representantes de ventas.

La app utiliza datos de backend mediante lib/api.ts, y provee componentes reutilizables con Radix UI y Tailwind CSS.

1. Estructura general

  • app/: páginas de Next.js.
  • components/: componentes UI y módulos de dashboard / envíos.
  • hooks/: hooks personalizados.
  • lib/: cliente de API, tipos y datos de prueba.
  • public/: recursos estáticos (vacío en este repositorio).

2. Páginas principales

app/page.tsx — Dashboard

Esta es la página inicial que muestra el panel general. Renderiza:

  • PeriodSelector para escoger el rango de fechas.
  • Cuatro KPI cards con clientes, entregas, utilidades y sales reps.
  • GraficaHistorico con la evolución mensual.
  • GraficaEstatus mostrando distribución de estados.
  • GraficaClientes con top clientes por utilidad.
  • TablaTopClientes y TablaTopSalesRep para listados de líderes.

Trae métricas desde panelApi en lib/api.ts.

app/operaciones/page.tsx y app/shipments/page.tsx

Ambas páginas muestran:

  • Un botón para abrir el ModalShipment.
  • TablaShipments con envíos.
  • TablaClientes y TablaSalesRep.

3. Capa de API

lib/api.ts define la comunicación con el backend:

  • get() y post() envían peticiones con fetch y manejan errores.
  • panelApi ofrece endpoints del dashboard: KPIs, series de tiempo, pie chart y top lists.
  • operacionesApi ofrece endpoints de envíos, clientes, reps y modelos predictivos.

También contiene los tipos de datos que espera el frontend, como KpiResponse, PieItem, ShipmentRow y más.

4. Datos de prueba y utilidades

lib/mock-data.ts contiene catálogos y datos estáticos:

  • CLIENTES, USUARIOS, LUGARES, ESTATUS_LISTA.
  • Datos para dashboard: KPI_DATA, HISTORICO, TOP_CLIENTES, TOP_SALESREP, SHIPMENTS.
  • Funciones de formato: formatMXN y formatMXNCorto.
  • Almacenamiento mutable de lugares con getLugares, agregarLugar y resetLugares.

5. Hooks y estado

hooks/use-filtros.ts expone:

  • filtros: estado global de filtros.
  • actualizarFiltro(clave, valor): actualiza un filtro específico.
  • limpiarFiltros(): elimina todos los filtros.

6. Módulos de interfaz

Los componentes en components/ui/ son wrappers de Radix UI para controles reutilizables:

  • button.tsx, input.tsx, select.tsx, card.tsx, dialog.tsx, popover.tsx, dropdown-menu.tsx, sheet.tsx, table.tsx, badge.tsx, separator.tsx, calendar.tsx, skeleton.tsx.
  • lib/utils.ts define cn(...inputs) para combinar clases CSS con clsx y tailwind-merge.

7. Componentes más importantes

Sidebar y ThemeProvider

  • components/layout/sidebar.tsx construye la barra lateral con navegación y cambio de tema.
  • components/layout/theme-provider.tsx agrega el proveedor de tema.
  • components/theme-provider.tsx añade un hotkey d para alternar tema.

Dashboard

  • components/dashboard/period-selector.tsx maneja rangos de fecha y valores predeterminados.
  • components/dashboard/kpi-card.tsx muestra tarjetas de KPI con variación y iconos.
  • components/dashboard/grafica-historico.tsx muestra una línea con series de órdenes y utilidad.
  • components/dashboard/grafica-estatus.tsx muestra un donut de estados.
  • components/dashboard/grafica-clientes.tsx muestra un gráfico de barras de top clientes por utilidad.
  • components/dashboard/tabla-top-clientes.tsx y components/dashboard/tabla-top-salesrep.tsx muestran listas de top rendimiento.

Envíos

  • components/shipments/tabla-shipments.tsx lista envíos con búsqueda, filtrado y paginación.
  • components/shipments/tabla-clientes.tsx y components/shipments/tabla-salesrep.tsx listan clientes y reps con filas expandibles.
  • components/shipments/modal-shipment.tsx es el formulario más complejo, con carga de datos, creación de clientes, reps y lugares, predicción de carrier y generación de ticket PDF.

8. Flujo de datos

La aplicación sigue este flujo general:

  1. El layout base envuelve el contenido con tema y sidebar.
  2. Las páginas usan hooks y componentes para construir la interfaz.
  3. Los componentes de dashboard llaman a panelApi para recibir métricas y gráficos.
  4. Los componentes de envíos llaman a operacionesApi para obtener listados, filtros y predicciones.
  5. Los datos estáticos de lib/mock-data.ts se usan como catálogos y ejemplos cuando no hay backend.

9. Notas importantes

  • El modal de envío es la parte más funcionalmente activa y usa muchos estados locales.
  • El proyecto está preparado para consumir un backend real, pero también funciona con datos de ejemplo en la carpeta lib.
  • El intercambio de tema se controla mediante next-themes y un atajo de teclado.
